# AGENTS.md

## Project Shape
- Backend is a Kotlin/Spring Boot app rooted at this directory; entrypoint is `src/main/kotlin/com/example/CrudApplication.kt`.
- Frontend is a separate Vue 3/Vuetify/Vite app in `client/agencia-viajes-client`.
- Frontend API base URL is hardcoded in `client/agencia-viajes-client/src/config/Config.ts` as `http://localhost:8080`.
- Frontend routing is generated by `unplugin-vue-router` from `src/pages`; do not add Nuxt-only APIs such as `definePageMeta`.

## Commands
- Backend dev: `./gradlew bootRun` from repo root. This task loads `.env` automatically if present.
- Backend tests: `./gradlew test` from repo root. Tests use `src/test/resources/application-test.yml` with H2 and do not require PostgreSQL or `.env`.
- Backend full verification: `./gradlew build`.
- Backend compile-only check: `./gradlew compileKotlin`.
- Frontend install/build/dev commands run from `client/agencia-viajes-client`.
- Frontend dev: `npm run dev -- --host`. Vite is configured for port `3000`; if occupied, Vite may choose another port.
- Frontend typecheck/build: `npm run build` (`vue-tsc --noEmit && vite build`).
- Frontend lint script runs with `--fix`: `npm run lint` modifies files.

## Environment And Persistence
- Required runtime env is documented in `.env.example`: `DATABASE_URL`, `DATABASE_USERNAME`, `DATABASE_PASSWORD`, `JWT_SECRET`, `OPENAI_API_KEY`, `CORS_ALLOWED_ORIGINS`, `FILE_STORAGE_PATH`, `FILE_STORAGE_MAX_IMAGE_SIZE_BYTES`.
- Dev JPA uses `ddl-auto: update`; prod profile uses `ddl-auto: validate`. There is no Flyway/Liquibase setup, so schema changes need explicit SQL/migration planning for production.
- Uploaded images are served from `/storage/**`; storage location comes from `FILE_STORAGE_PATH`.
- OpenAI integration must degrade gracefully; search/recommendation code has local fallback behavior and should not require a valid key for core app use.

## Security Rules That Matter
- Real roles are exactly `USER`, `ADMIN`, `SUPER_ADMIN`.
- Backend method security is enabled; do not rely on Vue route guards for authorization.
- User admin operations use DTOs in `UserAdminDtos.kt`; do not reintroduce generic `User` PUTs for sensitive fields.
- Actor identity must come from Spring Security/SecurityContext, never from request body fields such as actor id or actor role.
- Sensitive admin actions require current-password reauthentication in backend: deleting admins/superadmins, role changes, admin/superadmin email changes, password reset requests, and blocking/unblocking admins.
- Never store passwords, JWTs, or tokens in `AdminAuditLog`; audit only non-sensitive action metadata.
- `ADMIN` may manage `USER` accounts only and must never promote to `SUPER_ADMIN`.
- `SUPER_ADMIN` cannot delete itself or remove/degrade the last active `SUPER_ADMIN`; last-superadmin violations should return `409 Conflict`.

## Domain/UX Conventions
- Booking/reservation flow is external: hotel `externalUrl` opens Booking or another provider; the app does not process payments.
- Hotel cards should stay lightweight: image, name, location, short description, price, rating, key services, and `Acceder`. Keep email, phone, address, cancellation policy, and raw URL out of cards.
- Hotel detail/admin may show email, phone, address, cancellation policy, and full service data.
- `Destination.slug` is still the technical field used in routes/endpoints, but UI should label it as `URL key`, not `Slug`.
- Destination points of interest are structured as `pointsOfInterest`; legacy `popularAttractions` is hidden/compat-only and should not be used in new frontend code.

## Admin Filtering
- Admin filters for destinations/users are backend-backed via paginated endpoints, not frontend-only array filtering.
- Destination manager query params use `d_` prefixes; user manager query params use `u_` prefixes to preserve filter state.
- Reuse `components/admin/AdminFilterToolbar.vue` for admin filter UX instead of creating duplicate filter toolbars.

## Tests To Preserve
- `UserServiceTest` covers critical admin security rules; update it when changing user/role/delete/password-reset behavior.
- `CrudApplicationTests` loads the Spring context with the `test` profile; keep H2 test config aligned with new required properties.
